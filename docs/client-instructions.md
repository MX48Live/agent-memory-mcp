Read the current source code, config, tests, and repository docs for project work. ## Database and views

Eight input properties: Task (title), Date (date), Project (select), Minutes (number), Time Basis (select: Measured / Estimated / Unknown), Reference (URL), Entry ID (text), and Repository (URL). Three hidden boolean formula properties drive calendar views: This Week (Monday through Sunday), This Month, and Last Month. Date is date-only; reporting boundaries are Asia/Bangkok. Calendar formulas use Notion's current day, so exact reports must verify date boundaries rather than treating the user's Notion timezone as verified.

Five table views: All Logs (unfiltered, newest date first), This Week, This Month, Last Month (calendar period and grouped by Project), and Needs Review (non-measured/unknown time, missing required fields, or nonpositive Minutes). Entry ID and calendar helpers are hidden from normal columns. Outcomes, validation, and caveats belong in page content. Project options initially include agent-memory-mcp and General.

Prefer saved-view reads with pagination rather than relying on Free-plan SQL/rows quotas. Verify the actual saved formula filters: the MCP view DSL can silently omit formula-result conditions, so a successful configuration call alone is insufficient. Use supported Notion UI controls when needed, then fetch the resulting view state.
